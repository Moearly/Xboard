# XBoard 官方更新合并指南

## 📌 概述

本文档详细说明如何将 XBoard 官方更新合并到我们的多租户分支。

## 🎯 合并策略

```
官方仓库 (upstream/main)
    ↓
  合并到
    ↓
多租户分支 (origin/multi-tenant)
    ↓
  测试验证
    ↓
  部署上线
```

## 🔧 前置准备

### 1. 添加官方远程仓库（一次性）

```bash
cd /home/martnlei/codeSpace/XboradAll/VpnAll/xboard

# 添加官方仓库
git remote add upstream https://github.com/cedar2025/Xboard.git

# 验证
git remote -v
# 应该看到:
# origin    <your-repo> (fetch)
# origin    <your-repo> (push)
# upstream  https://github.com/cedar2025/Xboard.git (fetch)
# upstream  https://github.com/cedar2025/Xboard.git (push)
```

### 2. 保存当前工作

```bash
# 确保所有修改已提交
git status

# 如果有未提交的修改
git stash save "临时保存: $(date +%Y%m%d-%H%M%S)"
```

### 3. 切换到多租户分支

```bash
git checkout multi-tenant
git pull origin multi-tenant
```

## 📥 合并流程

### 步骤 1: 拉取官方更新

```bash
# 拉取官方最新代码
git fetch upstream main

# 查看官方更新内容
git log HEAD..upstream/main --oneline

# 查看修改的文件
git diff --stat HEAD..upstream/main
```

### 步骤 2: 创建合并分支

```bash
# 创建临时合并分支
git checkout -b merge-official-$(date +%Y%m%d)

# 示例: merge-official-20241125
```

### 步骤 3: 尝试自动合并

```bash
# 合并官方更新
git merge upstream/main --no-ff -m "merge: 合并官方 XBoard 更新 ($(date +%Y-%m-%d))"
```

### 步骤 4: 处理冲突

#### 如果没有冲突

```bash
# 显示: Merge made by the 'recursive' strategy
✅ 自动合并成功！继续下一步测试。
```

#### 如果有冲突

```bash
# 显示: Automatic merge failed; fix conflicts and then commit the result

# 查看冲突文件
git status
# 或
git diff --name-only --diff-filter=U

# 常见冲突文件:
# - app/Models/*.php
# - app/Http/Middleware/TenantIdentification.php
# - app/Support/Setting.php
# - config/app.php
```

## 🔧 冲突解决指南

### 冲突类型 1: 模型文件冲突

**示例**: `app/Models/User.php`

```php
<<<<<<< HEAD (我们的版本)
class User extends Model {
    use BelongsToTenant;  // 多租户 Trait
    
    protected $fillable = [
        'email',
        'password',
        // ...
    ];
=======
class User extends Model {
    protected $fillable = [
        'email',
        'password',
        'new_field',  // 官方新增字段
        // ...
    ];
>>>>>>> upstream/main (官方版本)
```

**解决方案**: 保留双方修改

```php
class User extends Model {
    use BelongsToTenant;  // ← 保留我们的 Trait
    
    protected $fillable = [
        'email',
        'password',
        'new_field',  // ← 保留官方新增字段
        // ...
    ];
}
```

### 冲突类型 2: 中间件冲突

**示例**: `app/Http/Middleware/TenantIdentification.php`

如果官方没有这个文件，不会冲突。但如果官方后续添加了类似功能，需要：

1. **仔细对比**两个版本的差异
2. **优先保留**我们的租户识别逻辑
3. **选择性合并**官方的改进（如性能优化、安全修复）

### 冲突类型 3: 配置系统冲突

**示例**: `app/Support/Setting.php`

```php
<<<<<<< HEAD
public static function get(string $key, $default = null)
{
    // 我们的多租户逻辑
    $tenantId = SharedSettings::getTenantIdForKey($key);
    return cache()->remember("setting_{$tenantId}_{$key}", 3600, function() use ($key, $tenantId) {
        // ...
    });
}
=======
public static function get(string $key, $default = null)
{
    // 官方的新逻辑（例如性能优化）
    return cache()->tags('settings')->remember("setting_{$key}", 3600, function() use ($key) {
        // ...
    });
}
>>>>>>> upstream/main
```

**解决方案**: 合并双方优点

```php
public static function get(string $key, $default = null)
{
    // ← 保留租户逻辑
    $tenantId = SharedSettings::getTenantIdForKey($key);
    
    // ← 采用官方的 cache tags（性能改进）
    return cache()->tags(['settings', "tenant_{$tenantId}"])
        ->remember("setting_{$tenantId}_{$key}", 3600, function() use ($key, $tenantId) {
            // ...原有逻辑
        });
}
```

### 冲突类型 4: 数据库迁移冲突

如果官方添加了新的迁移文件，一般不会冲突。但如果官方修改了已有表结构，需要：

```bash
# 查看官方的迁移
ls -la database/migrations/

# 检查是否与我们的 tenant_id 冲突
# 必要时调整迁移顺序
```

## ✅ 解决冲突后的步骤

### 1. 标记冲突已解决

```bash
# 编辑完冲突文件后
git add <冲突文件>

# 例如:
git add app/Models/User.php
git add app/Support/Setting.php
```

### 2. 完成合并提交

```bash
# 继续合并
git commit

# 会打开编辑器，使用默认提交信息或自定义:
# merge: 合并官方 XBoard 更新 (2024-11-25)
# 
# 冲突文件:
# - app/Models/User.php (新增 new_field 字段)
# - app/Support/Setting.php (采用 cache tags 优化)
```

### 3. 运行测试

```bash
# 运行自动化测试
./test-scripts/real-world-test.sh

# 或手动测试关键功能
php artisan tinker
>>> \App\Models\Tenant::count();
>>> \App\Models\User::where('tenant_id', 1)->count();
>>> config('v2board.site_name');
```

### 4. 检查数据库迁移

```bash
# 查看待运行的迁移
php artisan migrate:status

# 运行新的迁移
php artisan migrate

# 检查是否有遗漏的 tenant_id
# 必要时手动添加
```

### 5. 合并到主分支

```bash
# 测试通过后，合并到 multi-tenant 分支
git checkout multi-tenant
git merge merge-official-$(date +%Y%m%d) --no-ff

# 推送到远程
git push origin multi-tenant

# 删除临时分支
git branch -d merge-official-$(date +%Y%m%d)
```

## 🤖 自动化脚本

创建 `xboard/scripts/merge-official.sh`:

```bash
#!/bin/bash

set -e

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
PROJECT_DIR="$(dirname "$SCRIPT_DIR")"

cd "$PROJECT_DIR"

echo "📥 XBoard 官方更新合并脚本"
echo "================================"
echo ""

# 1. 检查当前分支
CURRENT_BRANCH=$(git branch --show-current)
if [ "$CURRENT_BRANCH" != "multi-tenant" ]; then
    echo "❌ 错误: 请先切换到 multi-tenant 分支"
    echo "   git checkout multi-tenant"
    exit 1
fi

# 2. 检查是否有未提交的修改
if ! git diff-index --quiet HEAD --; then
    echo "❌ 错误: 有未提交的修改，请先提交或 stash"
    echo "   git stash save \"临时保存\""
    exit 1
fi

# 3. 拉取官方更新
echo "📡 拉取官方更新..."
git fetch upstream main

# 4. 显示更新内容
echo ""
echo "📋 官方更新内容:"
echo "---"
git log HEAD..upstream/main --oneline --no-merges | head -10
echo "---"
echo ""

# 5. 询问是否继续
read -p "是否继续合并? (y/N) " -n 1 -r
echo ""
if [[ ! $REPLY =~ ^[Yy]$ ]]; then
    echo "❌ 取消合并"
    exit 0
fi

# 6. 创建合并分支
MERGE_BRANCH="merge-official-$(date +%Y%m%d-%H%M%S)"
echo "🔀 创建合并分支: $MERGE_BRANCH"
git checkout -b "$MERGE_BRANCH"

# 7. 尝试合并
echo "🔄 开始合并..."
if git merge upstream/main --no-ff -m "merge: 合并官方 XBoard 更新 ($(date +%Y-%m-%d))"; then
    echo "✅ 自动合并成功！"
    
    # 8. 运行测试
    echo ""
    echo "🧪 运行测试..."
    if ./test-scripts/real-world-test.sh; then
        echo "✅ 测试通过！"
        
        # 9. 合并到主分支
        echo ""
        echo "📦 合并到 multi-tenant 分支..."
        git checkout multi-tenant
        git merge "$MERGE_BRANCH" --no-ff
        
        echo ""
        echo "✅ 合并完成！"
        echo ""
        echo "下一步:"
        echo "1. 推送到远程: git push origin multi-tenant"
        echo "2. 删除临时分支: git branch -d $MERGE_BRANCH"
        
    else
        echo "❌ 测试失败，请检查"
        echo "   当前在分支: $MERGE_BRANCH"
        exit 1
    fi
else
    echo ""
    echo "⚠️  发现冲突，需要手动解决"
    echo ""
    echo "冲突文件:"
    git diff --name-only --diff-filter=U
    echo ""
    echo "解决步骤:"
    echo "1. 编辑冲突文件（参考 docs/04-开发文档/官方更新合并指南.md）"
    echo "2. git add <文件>"
    echo "3. git commit"
    echo "4. ./test-scripts/real-world-test.sh"
    echo "5. git checkout multi-tenant && git merge $MERGE_BRANCH"
    exit 1
fi
```

使用脚本:

```bash
# 赋予执行权限
chmod +x scripts/merge-official.sh

# 运行
./scripts/merge-official.sh
```

## 🚨 常见问题

### Q1: 合并后某些功能失效

**排查步骤**:

```bash
# 1. 检查日志
tail -f storage/logs/laravel.log

# 2. 清理缓存
php artisan cache:clear
php artisan config:clear
php artisan view:clear

# 3. 重新运行迁移
php artisan migrate

# 4. 检查租户配置
php artisan tinker
>>> app('currentTenant')
```

### Q2: 数据隔离失效

**检查点**:

```bash
# 1. 确认模型有 Trait
grep -r "use BelongsToTenant" app/Models/

# 2. 确认中间件注册
cat app/Http/Kernel.php | grep TenantIdentification

# 3. 测试查询
php artisan tinker
>>> app()->singleton('currentTenant', fn() => \App\Models\Tenant::find(1));
>>> \App\Models\User::count();  // 应该只返回租户1的用户数
```

### Q3: 合并后性能下降

**可能原因**:

1. 官方新增了日志或查询
2. 缓存策略改变
3. 中间件顺序变化

**解决**:

```bash
# 启用查询日志
DB::enableQueryLog();
// 执行操作
dd(DB::getQueryLog());

# 分析慢查询
tail -f storage/logs/laravel.log | grep "slow query"
```
